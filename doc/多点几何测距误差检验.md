# 多点几何测距误差检验

本工具复用原有相机采集、冻结原图、手工标点和输入实测 XYZ 的流程。
现在可以一次查看全部采集点的误差，也可以合并指定的多轮 CSV。不会拟合、修改内参或安装外参。

## 一、直接在标点窗口查看报告

在 `C:\Users\24435\Desktop\LingyanProVision` 目录双击 `start_geometry_validation.cmd`，或运行：

```powershell
& ".\.venv\Scripts\python.exe" -X utf8 -m calibration.collect_mount_points --camera usb0bda3035_1080p --purpose validation
```

1. 先关闭其他占用相机的窗口；旧版本标点窗口需要导出数据、关闭并重新启动才能出现新按钮。
2. 保持车辆、相机、安装支架和车体原点不变。拍摄并冻结画面，点选地面靶心。
3. 输入该点相对车体原点的实测 X/Y/Z，点击“添加这个点”；地面且车体原点在地面时 Z=0。
4. 继续添加其他不同位置的点。移动标记后应恢复实时画面并重新冻结，不能点击上一位置的旧冻结图。
5. 点击新增的“查看全部点误差”。程序使用**当前列表的全部点**生成报告，无需先导出 CSV。
6. 报告窗口可横向和纵向滚动。点击“保存 JSON + TXT”保存到该相机的 `calibration/results/` 目录。
7. 原来的“导出标定 CSV”仍需保留使用，便于之后重新计算和跨轮汇总；保存报告不等于导出了采集 CSV。

报告是点击按钮时的快照；修改或添加采集点后，应再次点击按钮生成新报告。
当前窗口用默认 2000 mm、3° 实时有效性门限，不自动设定误差合格标准。
已有相机均可用 `--camera <相机ID>` 选择，但必须有与当前内参匹配的有效安装外参。

## 二、从导出 CSV 计算全部点

读取默认 CSV、同时在终端显示逐点表与整体统计：

```powershell
& ".\.venv\Scripts\python.exe" -X utf8 -m calibration.validate_ranging --camera usb0bda3035_1080p
```

输入是 `calibration/data/usb0bda3035_1080p/range_validation.csv`，输出是：

- `calibration/results/usb0bda3035_1080p/range_validation.json`
- `calibration/results/usb0bda3035_1080p/range_validation.txt`

已有同名结果先备份；采集 CSV、照片、内参和安装外参不会被改写。
TXT 是人可读报告；JSON 保存逐点数值、来源 CSV 行号、原图路径、校准快照及文件 SHA256。
原有 `mean_horizontal_error_mm` 等字段保留兼容。

建议每轮 CSV 另存成独立名字；例如先在采集器导出 `geometry_round_01.csv`，再运行：

```powershell
& ".\.venv\Scripts\python.exe" -X utf8 -m calibration.validate_ranging --camera usb0bda3035_1080p --points ".\calibration\data\usb0bda3035_1080p\geometry_round_01.csv" --output ".\calibration\results\usb0bda3035_1080p\geometry_round_01.json"
```

输出同名 TXT。输入必须在本相机的数据目录，输出必须在本相机的结果目录，不能覆盖相机参数文件。

## 三、合并指定的多轮采集

在 `--points` 后列出多个**已导出的** CSV，例如：

```powershell
& ".\.venv\Scripts\python.exe" -X utf8 -m calibration.validate_ranging --camera usb0bda3035_1080p --points ".\calibration\data\usb0bda3035_1080p\geometry_round_01.csv" ".\calibration\data\usb0bda3035_1080p\geometry_round_02.csv" --output ".\calibration\results\usb0bda3035_1080p\geometry_combined.json"
```

每个 CSV 的每行都会计入，点号按指定文件顺序重新编号 P001、P002……，保留文件与原行号。
重复指定同一个文件会拒绝；不同文件中相同位置的记录会保留，供重复测量使用。
因此不要同时输入一份数据及其内容相同的备份，否则同一测量被重复计权。
“不同 XYZ 位置数”帮助识别多次测量与不同位置的区别。

合并时所有点统一使用**本次运行加载的内外参**重新计算，不合并旧 JSON 的平均值。
必须自行确认各轮的相机安装状态与车体坐标系一致；程序不能从 CSV 证明物理支架没有移动。

## 四、报告中的指标

每个点输出实测/计算 X、Y、水平距离和方位角，并计算：

- ΔX、ΔY：计算坐标减实测坐标，保留正负号。
- eXY：`sqrt(ΔX²+ΔY²)`，即水平位置误差。
- Δr：计算距离减实测距离，测远为正，测近为负。
- Δa：计算方位角减实测方位角，归一到 [-180°,180°)。
- 相对距离误差：`100 × abs(Δr)/r实测`。

整体统计包括平均带符号偏差、水平误差平均值/中位数/RMSE/P95/最大值、距离 MAE/RMSE、方位角 MAE。
还输出按实测前向 X 分组及按实测水平距离 r 分段的统计，默认 r 分段宽度 300 mm，区间为左闭右开。

P95 使用最近秩法：排序后取第 `ceil(0.95×n)` 个值；不超过 5 个有效点时等于最大值。
P95 只是样本描述，不是 95% 精度保证。不同位置的离散程度不能当成同一位置的时间抖动。
实测距离为 0 时，相对误差和方位角误差不可定义，显示 `--`，不除以零。
Z 是求交输入平面，不单独验证高度精度。

## 五、几何可解不等于实时可用

报告区分两种状态：

1. **几何有效**：像素在图内，射线与指定平面存在正向有限交点，可以计算误差。
2. **实时门限可用**：还满足当前运行程序的车体前方、距离上限、最小射线/平面夹角等要求。

超出实时距离上限或接近地平线，但几何仍可解的点，保留其误差并标记“有效/拒绝”；既不会当作实时可用，也不会隐藏其误差。
无几何解的点保留行号和原因，误差显示 `--`，不作为零误差混入均值。
报告分别给出全部几何有效点统计与仅实时可用点统计。
输入数字缺失、NaN/Inf 或列名错误则停止并报错，不生成混有非法数值的报告。

离线门限必须与你准备采用的实时设置一致。必要时指定：

```powershell
& ".\.venv\Scripts\python.exe" -X utf8 -m calibration.validate_ranging --camera usb0bda3035_1080p --range-max-mm 2000 --min-plane-angle-deg 3 --bin-mm 300
```

## 六、可选误差门槛

例如你决定以水平位置误差 20 mm 为单点标准，可加 `--max-error-mm 20`。
这是你设定的验收门槛，不是程序宣称相机已有 20 mm 精度。无效点不算“通过”，单独列出。
门槛仅考核 eXY，不同时考核方位角和距离误差；运行可用性与误差判定仍是两个独立条件。

没有采集的视野外位置不会出现在 CSV，必须继续在 40 点纯文本记录表里记录。
本报告不会凭已有点自动宣布连续有效范围，也不计算自动角点识别成功率。
