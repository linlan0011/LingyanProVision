# 灵眼 Pro 相机标定完整操作手册

本手册按原来的龙邱灵眼 Pro 编写，默认图像为 **640 × 480、不旋转、不镜像、不裁切**。流程依次完成镜头内参、车体安装外参和已知高度平面测距验证。彩钻风 Pro 的数据、照片和结果不能混进灵眼目录。

## 标定目标与产物

| 阶段 | 主要结果 | 默认文件 |
| --- | --- | --- |
| 镜头内参 | `fx, fy, cx, cy` 和 `k1, k2, p1, p2, k3` | `calibration/results/lingyan/intrinsics.json` |
| 内参留出验证 | 独立照片重投影误差及去畸变预览 | `calibration/results/lingyan/validation.json` |
| 装车外参 | `R_bc`、相机光心 `C_b=(a,b,h)` | `calibration/results/lingyan/mount_pose.json` |
| 测距验证 | 预测位置与尺量位置的误差、有效距离范围 | `calibration/results/lingyan/range_validation.json` |

棋盘格照片只能求镜头内参和每张照片中棋盘相对相机的姿态。它不会直接给出相机装车后的 `R_bc`、`C_b`。这两项需在相机固定到车上后，用车体系已知点另行标定。

## 准备物料

- 灵眼 Pro 相机、USB 数据线、电脑和最终使用的镜头。
- [A4 横向棋盘格 PDF](../output/pdf/lingyan_chessboard_9x6_A4_20mm.pdf) 和一张平整硬板。
- 钢尺或游标卡尺；平贴棋盘格的胶带或胶水。
- 相机固定支架；装车测量用卷尺、直尺、直角尺、地面标记贴。
- 一块平整场地，以及至少 12 个可清楚辨认、能尺量坐标的目标点。

棋盘格是 **10 × 7 个方格、9 × 6 个内部角点**，A4 版名义单格 20 mm、图案外廓 200 × 140 mm。打印时选 A4 横向、“实际大小／100%”，关闭“适合页面／缩放”，不要打印截图。量 PDF 下方的 100 mm 参考线，再量横向 10 格总宽度；将实测总宽度除以 10，作为后续命令的 `square_mm`。再量纵向核对比例。横纵缩放不一致时重印。将纸平贴硬板，避免弯曲、翘边和强反光覆膜。

## 第 1 步：固定相机成像设置

1. 使用最后比赛时的灵眼 Pro、镜头、USB 线和安装分辨率。
2. 本流程固定 `640 × 480`，不旋转、不镜像、不裁切。相机重新插拔或更换 USB 口后重新检查实际帧尺寸。
3. 固定机械对焦位置；不要在采图中拧镜头。若驱动支持自动对焦且无法关闭，先等焦点稳定，避免棋盘姿态改变时焦点跳动。
4. 当前驱动记录中，640 × 480 的 Media Foundation 模式报告 30 FPS；DirectShow 能力表另列 MJPG 60 FPS、YUY2 30 FPS。帧率报告不等于持续帧率实测。标定时不要临时切换分辨率或像素格式。
5. 曝光和白平衡保持一个稳定状态。当前相机配置记录中曝光和白平衡是自动模式；若手动更改，记录设置并确保最终识别也使用相同设置。设置详情见[相机标定配置记录](相机的标定配置.md)。
6. 检查 Windows 相机设备确实是本次要标定的灵眼 Pro。当前电脑曾枚举为 `Ubi Camera v4`（`VID_058F&PID_3866`），Windows 名称本身不能证明型号；如更换了设备，不要把这份记录套用到另一台相机。

## 第 2 步：采集内参求参照片

在 VS Code 打开 `C:\Users\24435\Desktop\LingyanProVision`，运行任务 **Calibration: capture chessboard**。也可以在 PowerShell 中运行：

```powershell
Set-Location "C:\Users\24435\Desktop\LingyanProVision"
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera lingyan --index 0
```

程序先打开相机并读取首帧，确认尺寸是 640 × 480；若打开后没有帧或尺寸不符，会停止，避免采错模式。预览中的 `FOUND` 表示找到了完整 9 × 6 内角点。画面稳定且整块棋盘清楚可见时按空格保存；`NOT FOUND` 时不要保存，按 `q` 或 `Esc` 退出。

求参集拍 24～30 张，默认存入 `calibration/data/lingyan/train`。让相机与棋盘距离、棋盘位置和朝向都变化：

| 变化项目 | 具体摆法 |
| --- | --- |
| 距离 | 近、中、远三档；棋盘宽度约占画面 60%～70%、40%～50%、20%～30%。太远导致方格看不清时不要继续后退。 |
| 画面位置 | 中央、左上、右上、左下、右下，以及上/下/左/右边缘。整块棋盘及外围方格须留在画面内。 |
| 左右倾斜 | 棋盘绕竖直方向向左、向右转约 15°～30°。 |
| 上下倾斜 | 棋盘上沿或下沿朝镜头倾斜约 15°～30°。 |
| 画面内旋转 | 少量照片将棋盘平面内转一个小角度；不能只靠这种旋转增加姿态变化。 |

推荐拍法：近、中、远每档约 8～10 张；每档都包含中央、不同边角和不同倾斜角。每次移动后停稳再保存，避免模糊及大量重复连拍。倾斜后棋盘应呈明显透视梯形，但四边和所有内角点仍完整可见。棋盘画面覆盖要跨到边缘，因为边缘畸变需要边缘样本来约束。

程序窗口里检测到棋盘不代表这张照片一定有用；保存前检查无运动模糊、过曝、强反光或手遮挡。数据目录里已有旧照片时，先确认它们同样是灵眼 640 × 480、同一旋转状态和同一镜头焦点，不要混入彩钻风照片。

## 第 3 步：采集内参留出验证照片

另拍 6～10 张不同姿态，保存到独立的 `calibration/data/lingyan/validation`，这些照片不参与求参。运行 VS Code 任务 **Calibration: capture validation images**，或执行：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera lingyan --index 0 --output "calibration/data/lingyan/validation"
```

不要把 `train` 照片复制到 `validation` 冒充独立验证集。若误把所有照片拍进 `train`，挑出 6～10 张不同姿态移动到 `validation`，确保求参时只读取 `train`。

## 第 4 步：求内参并检查留出误差

把命令中的 `20.0` 换成打印后实测的单格边长（毫米）：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.calibrate_intrinsics --square-mm 20.0
& ".\.venv\Scripts\python.exe" -m calibration.validate_intrinsics
```

也可以运行 VS Code 任务 **Calibration: solve intrinsics**，提示框内输入实测尺寸，再运行 **Calibration: validate intrinsics**。求参程序要求照片至少为 640 × 480、至少 10 张有效棋盘照片；实际建议 24～30 张。它输出相机矩阵、5 个针孔畸变系数、总重投影 RMS 和逐张误差。

验收时看三项：求参 RMS 目标 ≤0.5 px；留出集平均 RMSE 目标 ≤0.8 px、单张最大值目标 ≤1.5 px；查看 `validation_previews` 中原图与去畸变图，确认画面边缘没有明显残余弯曲。数值是工程目标，不是绝对标准。误差偏大时，先检查纸板是否平、格长测量是否准确、图像是否模糊以及姿态是否重复。不要为了压低 RMS 随意删掉困难照片。

结果写入 `calibration/results/lingyan/intrinsics.json`，验证数据写入同目录的 `validation.json` 和 `validation_previews`。当前求参程序使用普通针孔模型；如果边缘残差仍呈明显系统性弯曲，需要先实现并验证鱼眼模型，不能将针孔畸变系数当成鱼眼系数使用。

## 第 5 步：定义车体系并测相机安装位置

先把相机以最终角度刚性固定在车上。建议车体系原点取车体定位／里程计参考点在地面的投影，并统一定义：X 向前、Y 向左、Z 向上，地面为 Z=0。若项目里的里程计原点在离地位置，必须按那个实际定义填写点位高度，不能仍把地面点写成 Z=0。

从镜头光心估算相对车体原点的位置 `C_b=(a,b,h)`，用毫米记录；同时记录相机大致俯仰、偏航、横滚方向。这些是检查拟合结果的实测参考值。不要把棋盘照片中的相机/棋盘外参当成装车 `R_bc`。

## 第 6 步：测已知点并拟合装车外参

在平整场地布置至少 12 个可辨认点，覆盖左、中、右与近、中、远。可以先按前向约 500、1000、1500、2000 mm，横向约 -400、0、+400 mm布点，再按安全区实际尺寸调整。点不要排成一条直线；若能精确测出几个不同高度的点，也加入以增强约束。

每个物理点须对应同一个图像点，记录：

| 列名 | 内容 |
| --- | --- |
| `x_mm, y_mm, z_mm` | 点相对车体原点的真实坐标，毫米 |
| `u_px, v_px` | 点在未缩放、未旋转的 640 × 480 原图中的像素坐标；左上角为(0,0)，u向右、v向下 |

推荐使用新的[标定点采集工具](标定点采集工具说明.md)：双击项目根目录 `start_calibration_points.cmd`，或运行 VS Code 任务 **Calibration: collect mount points (LINGYAN)**。先关闭其他占用相机的程序，冻结清晰画面后逐点点击标记中心，填写该点实测 X/Y/Z，点击“添加这个点”。采集完成后“导出标定 CSV”，默认写入 `calibration/data/lingyan/mount_points.csv`。原文件存在时会先保留带时间戳的备份；本次原图和草稿保存在 `calibration/data/lingyan/point_sessions/` 下的独立目录。

工具是人工点选，不会自动识别任意标记。建议采用平贴地面的哑光黑白十字靶，测量和点击都取中心线交点。相机、车辆、车体系原点在同一批采集中不得移动。放大显示会自动换算回原图像素，不改变内参。若手动填写模板，必须把实测坐标及所有像素占位值替换为真实数据；重复像素或共线点会被外参拟合程序拒绝。

也可在原识别程序按 `s` 保存 `照片/latest_live_raw_lingyan.png` 后，点击采集工具的“打开原图…”；不要使用左右拼接的预览图、去畸变图或截图。再次按 `s` 会覆盖旧图。像素坐标以 640×480 原始成像为准。

运行 **Calibration: fit mount pose**，或：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.fit_mount_pose
```

程序使用 `solvePnPRansac` 拟合并输出 `R_bc`、`C_b` 和重投影误差到 `calibration/results/lingyan/mount_pose.json`。脚本最低接受 6 个点，现场建议使用 12 个以上并做独立验证。检查相机高度、前后左右偏移是否接近尺量值；内点 RMSE 目标 ≤1.5 px，离群点应回查像素和坐标记录。

## 第 7 步：用独立地面点验证测距

再选一批**没有用于外参拟合**的地面点，覆盖左右两侧和实际工作距离；可以每 250～500 mm 设一档。运行任务 **Calibration: collect range validation points (LINGYAN)**，或运行 `python -m calibration.collect_mount_points --purpose validation`（使用项目虚拟环境）。操作与外参采点相同，但默认导出到 `calibration/data/lingyan/range_validation.csv`，不会覆盖外参采点文件。也可手动填写 `calibration/range_validation_template.csv`，把占位坐标和像素值全部换成实测值。

对地面角点，`z_mm=0`（前提是上一步的车体原点定义使地面高度确为0）；围栏顶部必须使用实测离地高度。运行 VS Code 任务 **Calibration: validate ranging**，或：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.validate_ranging
```

程序逐点报告预测 X/Y、前向/横向误差和水平误差，结果写入 `calibration/results/lingyan/range_validation.json`。初步工程目标可用主要工作区平均水平误差 ≤30 mm、最大误差 ≤60 mm，最后按机器人定位和避障容差确定。按距离档检查误差，超出有效精度的位置不要继续外推。

单像素检查可运行以下命令，`320 360` 只是示例：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.ground_project 320 360 --target-z-mm 0
```

它执行去畸变、像素视线转车体系、与已知高度平面求交，输出相对车体原点的 X/Y/Z、水平距离和方位角。未知高度的普通图像角点，单个像素无法唯一确定米制距离；射线接近平面时距离误差会放大。

## 完成检查与使用边界

完成后应有 `intrinsics.json`、`validation.json`、`mount_pose.json`、`range_validation.json` 四类结果；原始棋盘照片和 CSV 也要保留，方便复查。每个参数文件都只适用于对应相机、分辨率、方向、镜头焦点及安装状态。

当前识别程序输出识别角点，但尚未自动加载上述 JSON 并在实时画面中输出米制距离；本流程会先把参数和误差验证好，实际识别接入还需把 `undistortPoints` 与射线平面求交逻辑接到角点坐标上。车辆运动时再单独检查相机、IMU、里程计时间同步及支架振动。
