# 最近角点身份与视觉绝对位姿（2026-10-15）

当前主循环使用此流程。旧上下沿分类及观测误差圆共同交集已移除；历史文档中的 UP/LOW、最远点传播、30/50 mm 圆域匹配和“仅反算位置不更新航向”不再描述当前实现。

## 运行顺序

1. 三种模式统一使用紫色分割、紫白有效边界、碎段合并、直线拟合及直接/补偿交点检测。2026-10-16起侧面也接入正面同一流程，保留自身分割与亮度预设，不再使用旧侧面凸角、近邻点取低点及标点后重新找支持边的路径。
2. 使用全部标出角点的 Z=0 几何投影距离进行排序，包括补偿角点，直接选择水平距离 r 最小的有效点。不存在上下沿类别；定位基准点标为 `NEAREST`，青色圆环。
3. 量程不参与几何排序。最近点选出后，检查定位测距是否有效，默认 r≤1000 mm。超量程或缺边时本帧不更新，不切换到第二近点。
4. 保留原来的安全区预筛：输入位置默认200 mm误差圆，输入航向固定，结合当前标定的地面视野与定位量程，对八个地图角点检查可能可见性。某区至少一角可能可见，就保留该区。这里的圆仅生成候选安全区，绝不匹配实际测量角点。
5. 读取检测器生成该交点时的两条支持边。三种模式均沿真实支持轮廓取样；使用校正像素路径时先转换回原始像素，再按已有相机参数投影到车体地面。不会通过遮挡空隙插入观测样本。
6. 对各条地面样本拟合直线，按角点指向真实支持区的方向确定正负。短边、残差过大、支持跨越角点、方向不清或不满足正交容差时不更新。
7. 两条车体系有向边与输入航向组成地图预测方向，在候选安全区的四个角之间匹配。枚举两条边的对应顺序，要求两条边都通过身份角度容差。只接受唯一身份和唯一边对应；两个安全区都相容时保持待定。
8. 身份确定后，地图边绝对方向减去视觉边车体系方向，分别获得两个视觉航向；一致时取圆周平均。最终航向数值不对输入航向加权或回退。
9. 根据已确认地图角点、角点相对车体坐标与视觉航向反算绝对 XY。更新独立视觉位姿，通过实时报告回传给地图 UI。
10. 地图红色箭头为输入位姿，青色箭头为视觉校正位姿；同时显示两套 XY/航向及差值。输入文件不被反馈覆盖。输入变化、反馈过期、无效帧或相机退出时清除旧视觉箭头。

## 几何与角度

车体 X向前、Y向左、Z向上。地图原点在左下，X向东、Y向北，航向0°朝东、90°朝北、逆时针为正。惯导航向须先与此坐标约定对齐。

设角点车体系坐标 C_B，两条边的车体系有向角 β1、β2，输入航向 θg。身份匹配采用：

`αi = wrap(θg + βi)`

地图四角：`.1 西北=东+南`，`.2 东北=西+南`，`.3 东南=西+北`，`.4 西南=东+北`。每区固定编号与外框坐标继续读取 `safety_templates.json`。

身份与边对应确认后，地图边方向 φi 已知：

`θvi = wrap(φi - βi)`

`θv = atan2(sin(θv1)+sin(θv2), cos(θv1)+cos(θv2))`

`pv = M - R(θv) C_B`

若使用角点水平距离 r 和车体系方位 γ，同一位置公式为：

`Xv = Mx - r*cos(θv+γ)`

`Yv = My - r*sin(θv+γ)`

输入 XY只影响安全区视野预筛，输入航向参与视野预筛和离散身份选择。在选中同一对应分支、检测与标定不变时，最终视觉位姿不随输入位姿数值漂移而连续变化。

## 参数与启动

| 参数 | 默认 | 调节方式 |
|---|---:|---|
| 安全区视野位置误差半径 | 200 mm | `--pose-radius-mm`；P窗口 `pose radius mm` |
| 定位量程 | 1000 mm | `--range-max-mm` |
| 身份方向匹配容差 | 15° | `--identity-angle-tol-deg`；`identity tol deg` |
| 地面边正交容差 | 15° | `--orthogonal-angle-tol-deg`；`orthogonal tol deg` |
| 两条视觉航向一致性容差 | 15° | `--heading-consistency-deg`；`heading tol deg` |
| 最小地面支持跨度 | 20 mm | `VisualPoseConfig.minimum_edge_span_mm` |
| 最大地面拟合/角点到线残差 | 20 mm | `VisualPoseConfig.maximum_line_residual_mm` |

角度滑条范围0～44°，0代表严格匹配。上述角度、跨度和残差均为工程测试初值，需要实拍验证。

## 回传和条件

顶层报告保持 `camera.simulated_pose_association.v1`，新增 `visual_pose`，内部格式为 `safety.nearest_visual_pose.v1`。包括最近点、两条地面边、候选安全区视野、身份假设、校正位姿与差值。

成功时 `status=corrected`、`pose_corrected=true`、`corrected_pose={x_mm,y_mm,heading_deg}`；失败时 `corrected_pose=null`、`pose_corrected=false`。`input_pose_overwritten=false`区分独立校正结果和原始输入。界面校验帧与输入、顶层与内部编号/位姿一致后，才显示青色箭头。

最近点及其支持边按地面模型处理，是本算法的物理假设，排序本身不能证明这一点。两条边实际上跨高度、相机支架姿态变化或标定错误时，投影可能错误；拟合与正交检查不是地面属性的充分证明。

当前接口输入仍是 UI模拟位姿。真实车辆运行还需要相机拍摄时间与惯导位姿对齐；回传年龄不等于拍摄延迟。该实现生成视觉绝对位姿，不包含里程计状态估计器或硬件运动控制。
