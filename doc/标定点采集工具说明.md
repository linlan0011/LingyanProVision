# 灵眼装车标定点采集

这是人工点选工具，不是紫色边框检测器，也不要求标记使用二维码或 ArUco 编码。程序取得原图像素 `(u,v)`；你负责尺量同一物理点相对车体原点的 `(X,Y,Z)`。

## 标记怎么做

- 推荐用约 80～100 mm 见方的哑光白纸，画一个居中的黑色 `+`。黑线可先用约 2～3 mm 宽、总长约 50～70 mm。尺寸是制作起点，不是固定要求；以最终距离和视角下能清楚分辨中心为准。
- 点击的是两条线**中心线的交点**，不是黑色粗块的角、纸张角或十字端点。尺量坐标时也必须测到这个交点。
- 中心不要涂成大黑圆。若远处细线看不清，放大整个靶标或适当加粗，不要凭模糊色块猜中心。可用工具的放大显示和局部像素放大图辅助观察。
- 另一个选择是 **2×2 黑白相间的方格靶**（对角同色），整张约 80～120 mm 见方；取四个方格共同交汇的那个中心角点。这种靶不依赖细线可见，更适合十字细线在远处消失的情况；仍须确认地面斜视下能看清交点。
- 白纸平贴地面，避免翘起、反光、胶带盖住中心。编号如 P01、P02 写在靶标边缘，与中心保持距离，防止对应错误。
- 不要求每张纸尺寸精确一致，也不靠十字宽度求距离。真正需要准确测量的是**各交点的车体系坐标**。
- 地面不是白色时也可画白色十字或使用其他高对比标记，但整批采用同一种样式更容易辨认。
- 若标记放在厚板、物体顶部等处，要填写交点真实 Z 高度。薄纸的厚度可在符合测量精度要求时忽略。

建议至少 12 点，分布在近、中、远和左、中、右；不能全排成一直线。以能看清靶心为前提覆盖实际测距区域。可先用 4 个前向距离 × 3 个横向位置，具体距离根据相机视野调整。测量时车辆按比赛状态放稳，相机支架固定。

## 打开工具

1. 关闭其他摄像头识别、棋盘采集、Windows 相机程序，避免争用设备。
2. 双击项目根目录 `start_calibration_points.cmd`。
3. 或在 VS Code 运行任务 **Calibration: collect mount points (LINGYAN)**。

PowerShell 等效命令：

```powershell
Set-Location "C:\Users\24435\Desktop\LingyanProVision"
& ".\.venv\Scripts\python.exe" -m calibration.collect_mount_points
```

工具自动尝试原灵眼 index 0、640×480、不旋转。设备序号不同时可加 `--index 1`。
若没有相机也可点击“打开原图…”，或加 `--image "原图绝对路径"`。图片必须是该灵眼同一焦点、同一安装状态拍摄的 640×480 原始图，不能是去畸变图、缩放图或左右拼接预览图。程序能检查尺寸，但不能仅凭图片判断设备身份或是否被镜像。

## 每个点怎么采

1. 将相机和车辆固定不动。一次冻结包含多个靶标的画面最方便。
2. 画面清晰、无晃动时点击“冻结画面”。只有冻结后才能采点。
3. 左键点击一个十字中心。黄色十字显示当前选点，右侧显示原图 u、v。
4. 必要时将显示放大设为 2 或 3，用滚动条查看局部。放大仅影响显示；像素自动换算回 640×480 原图。右侧局部图中心黄色框表示鼠标所在的原始像素。点选为整数像素，不宣称亚像素精度。
5. 输入**这个靶心**相对车体原点的 X、Y、Z，单位毫米：X 向前为正，Y 向左为正、向右为负，Z 向上为正。地面 Z=0 仅在车体原点选在地面时成立。不要填写镜头到点的斜距，也不要把相机光心坐标填进每一行。
6. 点击“添加这个点”。表格新增一行，原图标为绿色编号；X、Y 会清空，避免沿用上一个点的坐标。Z 保留，换高度时要主动修改。
7. 继续点下一个靶心。填错时在表格选择错误行，点击“删除选中行”，再重新采点。
8. 一张图不够时可继续实时预览/打开另一张原图，但**车辆、相机、焦点、车体系原点必须完全不变**。移动标记后重新测其坐标；若车辆或相机动过，结束这批，重启工具新建采集批次，不能混合拟合。
9. 采够后点击“导出标定 CSV”，保留默认路径 `calibration/data/lingyan/mount_points.csv`。外参最少 6 点，建议至少 12 点；重复像素、重复物理坐标、共线点或非有限数字会拒绝。

当前工具不自动测量 XYZ、不自动判断是否发生物理移动，也不自动修正点选误差。遮挡、模糊或找不到中心时不要采入。

## 保存与下一步

- 每次添加/删除都会自动更新时间戳会话目录内的 `points.csv` 和 `session.json`；首次添加该冻结画面的点时另存一张不带标注的 PNG。
- 会话目录在 `calibration/data/lingyan/point_sessions/`，记录每点的原图路径与本次内参文件摘要，可追查对应关系。重启工具会新建批次，不会自动加载旧草稿。
- “导出标定 CSV”才会更新下游读取的文件。若目标已存在，先备份为 `mount_points.backup_时间戳.csv` 再写入。没有导出的修改不会进入默认拟合程序；退出时会提醒。
- 新 CSV 前五列保持 `x_mm,y_mm,z_mm,u_px,v_px`，额外的 `frame_file` 用于追溯，已有拟合程序兼容。
- 工具不会改动 `intrinsics.json`、旧照片或已有 `mount_pose.json`，也不会自动计算外参。旧的不合理外参结果仍不能用于测距。

导出真实数据后运行 **Calibration: fit mount pose**。程序联合求解安装旋转 `R_bc` 和光心坐标 `C_b`，再把结果与第五步实测光心坐标比较；低重投影误差并不单独证明结果正确。

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.fit_mount_pose
```

然后保持同一安装状态，另取没有参与拟合的点做验证。运行任务 **Calibration: collect range validation points (LINGYAN)**，或：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.collect_mount_points --purpose validation
```

这时默认导出 `calibration/data/lingyan/range_validation.csv`。最后运行 **Calibration: validate ranging**，或：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.validate_ranging
```
