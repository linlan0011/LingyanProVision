# 多相机独立标定与识别切换

本项目把**一个相机 ID**定义为同一台设备在固定的采集分辨率、镜头焦距与对焦、画面旋转方向、镜头模型下的一套配置。更换实体相机或改变其中任何成像条件，应注册新 ID，重新完成内参、安装外参和独立测距验证。相机序号 `--index` 只是 Windows 当前连接顺序，不能证明设备身份。

现有内置配置：`lingyan` 为原灵眼 640×480、不旋转；`seekfree` 为已记录的彩钻风采集 768×1024、顺时针旋转为 1024×768。内置配置代表可选择的采集模式，**不代表它们已经全部完成米制测距标定**。运行 `python -m camera_profiles list` 可查看每个 ID 的内参与外参状态。

## 2. 注册独立相机 ID

以下命令中的宽高只是示例，必须换成上一步实测并选择的实际模式。`hd_camera_01` 是可以自定义的独立名称。

```powershell
& ".\.venv\Scripts\python.exe" -m camera_profiles add hd_camera_01 --name "新高分辨率相机" --width 1920 --height 1080 --rotation none --model opencv_pinhole --index 0 --notes "记录设备标签、镜头焦距、对焦位置"
& ".\.venv\Scripts\python.exe" -m camera_profiles list
```

注册文件是项目根目录 `camera_profiles.json`，不会改写灵眼内参。ID 不能重复；若后来改变分辨率、焦距、对焦、旋转或镜头模型，应换一个新 ID。若实际镜头畸变很大，可为新 ID 选择 `--model opencv_fisheye`；两种畸变参数不能混用。没有证据表明镜头是鱼眼时，先用普通针孔模型并检查留出集边缘残差。

每个 ID 的默认目录：

| 阶段 | 输入／输出位置 |
| --- | --- |
| 求内参照片 | `calibration/data/<ID>/train/` |
| 内参留出照片 | `calibration/data/<ID>/validation/` |
| 地面采点 | `calibration/data/<ID>/mount_points.csv` |
| 独立测距点 | `calibration/data/<ID>/range_validation.csv` |
| 内参／外参／验证结果 | `calibration/results/<ID>/` |

标定命令禁止把已注册相机的默认产物写进另一个 ID 的目录。参数文件保存相机 ID、原始采集尺寸、旋转方向与镜头模型；外参还记录内参文件的 SHA-256 摘要。识别程序读取所选相机状态并检查这些信息。不能仅凭 USB 索引自动验证设备序列号，所以接线变化后仍需人工核实设备身份。

## 3. 内参：采图、求参、留出验证

可在 VS Code 使用名称含 **selected camera** 的任务，输入刚注册的 ID。或逐条运行：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera hd_camera_01
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera hd_camera_01 --output calibration/data/hd_camera_01/validation
& ".\.venv\Scripts\python.exe" -m calibration.calibrate_intrinsics --camera hd_camera_01 --square-mm 19.12
& ".\.venv\Scripts\python.exe" -m calibration.validate_intrinsics --camera hd_camera_01
```

`19.12` 仅是之前那张棋盘格的记录值；要复核你**实际使用的那张纸**的单格边长并替换。棋盘仍为 9×6 内角点。训练照片建议 24～30 张，留出 6～10 张，包含近中远、四角和不同倾角。相机自动检查实际采集尺寸与已注册尺寸一致。留出误差与边缘校正效果不满足要求时，检查棋盘平整度、清晰度、焦点和是否该使用鱼眼模型。留出照片不能从训练集复制。

## 4. 装车外参：采点、拟合

将**新相机**以最终姿态固定在车上。所有标记点的 XYZ 必须相对于同一个车体原点，X 向前、Y 向左、Z 向上；若把地面定义为 Z=0，就测靶心的地面坐标。目标至少 12 个，覆盖实际测距范围的近远与左右，勿全部在同一条线。相机、支架、车辆和车体原点在一批采集中不得改变。

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.collect_mount_points --camera hd_camera_01
& ".\.venv\Scripts\python.exe" -m calibration.fit_mount_pose --camera hd_camera_01
```

采点工具根据所选相机的分辨率、方向和内参打开画面，支持缩小／放大点选，并把点位及原图放到 `calibration/data/<ID>/point_sessions/`。拟合后检查内点比例、重投影误差及光心位置与尺量是否相符。低像素残差不等于米制距离正确。镜头内参变动后必须重新拟合外参。

## 5. 用未参与拟合的点验证测距

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.collect_mount_points --camera hd_camera_01 --purpose validation
& ".\.venv\Scripts\python.exe" -m calibration.validate_ranging --camera hd_camera_01
```

`range_validation.json` 给出每个点的预测车体系位置和水平误差。按比赛实际工作距离、左右位置分别看误差；只在实测可靠范围内使用。

## 6. 选择相机运行识别

查看列表：

```powershell
& ".\.venv\Scripts\python.exe" -m camera_profiles list
```

单独运行检测：

```powershell
& ".\.venv\Scripts\python.exe" purple_camera_segmentation.py --camera hd_camera_01 --scene auto
```

地图与识别联动：

```powershell
.\start_app.cmd --camera hd_camera_01
```

VS Code 对应任务为 **Camera: run selected profile recognition** 和 **Camera: run full app with selected profile**；输入 `lingyan` 或已注册的新 ID。启动时会显示所选内参／外参是否可用，且实际图像尺寸不匹配时停止。未知新相机目前沿用灵眼的紫色目标识别规则作为起点，颜色阈值、边缘尺度、视角模板还需新设备现场验证和调整。当前实时识别画面尚未把检测角点自动转换成米制距离；标定完成后再接入已知高度平面求交，围栏顶部不能当作地面点。
