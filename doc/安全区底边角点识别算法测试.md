# 安全区底边角点识别算法测试

## 1. 目的和适用范围

分支：`安全区底边角点识别算法测试`。

本次算法在已有的**全部可见角点、补偿角点提取完成后**执行。紫白颜色分割、有效边检查、局部直线分组、拟合、角点求交继续使用已有算法。分类时筛除上沿点，只影响分类的候选集合，原图和二值图仍显示全部角点。

本分支默认在正面 `front-facing` 和通用 `general` 模式启用。发车侧面 `start-facing` 模式继续使用原有规则。惯导先验仍用于原有场景和地图身份选择，本次新增的是上沿、下沿分类，尚不确认地图角点编号，也不执行位姿修正。

## 2. 对这个方案的评价

该规则适合做可检验的场景假设：远端上沿可以直接识别或补偿得到时，用最远点及其直接相连点排除一部分上沿，再以最近点和已知底边长宽寻找下沿。

它不能保证“最远必为上沿”或“最近必为下沿”。远端底角也可能比近端上角更远；结构斜边可能连接不同高度；最远点测距误差会影响后续分类。补偿角点的误差还会被投影测距放大。因此画面中的 `UP`、`LOW*`、`LOW` 都是本规则的分类假设，不是独立测得的高度。

建议以标注好真实上下沿的多角度图片检验上下沿准确率、下沿种子正确率、有效输出率和位置误差。后续可以利用已知上下沿三维尺寸、相机标定及惯导先验，比较整组角点的投影误差，以进一步验证本规则给出的假设。

## 3. 测距含义和参数

2026-10-14当前修正：恢复默认1000毫米定位测距上限；此上限只限制定位测量和地图匹配，**不限制上下沿分类的全体几何排序**。超量程点仍通过独立的几何投影参与排序，不会让第二远的点替代真正最远点。最远点仅向直接相连点传播一次UP的修正继续保留。新增的[圆域匹配与仿真位姿融合](安全区下沿角点圆域匹配与仿真位姿融合.md)仅对量程内的LOW*/LOW另行判断地图身份。

恢复原因：取消上限后，无限地面视野需要随先验位姿构造动态计算窗口；每帧重复执行3次动态多边形裁剪，诊断中视野相关累计耗时达2795.7毫秒，导致明显卡顿。现在使用启动时缓存的1000毫米车体系地面视野，每帧只进行航向旋转和位置平移。此次恢复上限与保留完整排序分别处理，不回退到提前排除最远补偿点的旧规则。

| 参数 | 当前值 | 说明 |
| --- | --- | --- |
| 底边长 | 660 mm | 用于点间距离匹配 |
| 底边宽 | 360 mm | 用于点间距离匹配 |
| 长宽匹配容差 | ±30 mm | 参数窗口 `bottom tol mm`，范围 0～200 mm |
| 投影平面 | 车体 Z=0 mm | 假定车体处于平稳、地面对应此高度的状态 |
| 定位有效测距上限 | 1000 mm | 只限制定位测量和地图匹配；完整几何排序不受此上限限制 |

分类前使用同一相机内参和安装外参，将所有可见、补偿角点的像素射线投影到 Z=0 平面，得到车体坐标 `(X,Y)`，按 `r = sqrt(X²+Y²)` 排序。这是相对车体原点的水平投影距离，不是独立深度测量；上沿点的 Z=0 投影并非该上沿点的真实三维位置。

先验上沿高度约20 mm、上口约600×300 mm，目前没有用于本分类器的测距或匹配，避免在身份尚未判断时预先指定不同高度。本轮测试验证的是用户提出的距离排序规则。

若缺少有效标定、设置了非零测距平面，或任一候选点因接近地平线、标定变化等原因无法进行有效几何投影，则本帧不输出下沿种子，不用部分点替代完整候选集合。若没有超量程点的几何距离则返回 `ranking_incomplete`。原始角点继续显示。

## 4. 具体分类流程

### 4.1 候选数量达到3个

1. 对全部候选点测距，补偿点也参与。相同整数像素的可见点和补偿点只计一个，优先保留可见点。
2. 选择距离最远点，标为上沿 `UP`。
3. 将与最远点通过同一条有效拟合边直接相连的候选点也标为 `UP`。
4. 从分类工作集合中移除这些上沿假设，其他点继续参与下沿判断。
5. 取剩余点中最近的点作为下沿种子 `LOW*`。种子依赖“最近”的假设，不要求先通过长宽检验。
6. 对其他剩余点，计算与种子的平面距离：

   `d = sqrt((X-Xseed)² + (Y-Yseed)²)`

   若 `abs(d-660) ≤ tolerance` 或 `abs(d-360) ≤ tolerance`，标为其他下沿点 `LOW`；否则保留为未分类点。

上沿筛除后若无剩余点，本帧无下沿种子。此处数量判断在筛除前进行；不会因筛除后不足3个而重新启动少点分支。

按用户要求，仅匹配底边长度或宽度。底面对角线约752 mm，当前不计入可接受距离。因此与种子相对的底角可能保留为未分类，当前也未要求不同匹配点共同组成完整矩形。

### 4.2 只有1个或2个候选

完成测距后，**直接将最近的候选点标为下沿种子 `LOW*`**。

不执行最远点上沿筛除，也不对另一个点执行长宽匹配。另一个点继续显示并保持未分类。只有1个候选时，该点即为种子；补偿点也可以成为种子。

### 4.3 没有候选

本帧不输出下沿种子，不沿用上一帧标签。

### 4.4 “直接相连”的定义

使用边界提取阶段已经接受的角点支撑线编号 `line_id`。两个角点必须使用同一条有效拟合边；在该边方向上，将使用这条边的角点排序，仅连接相邻两个角点。

拟合边可以跨越已有算法认可的遮挡缺口、延伸到已接受的补偿角点。该分类器不会因为像素距离近、方向近或两点看起来共线而建立连接，也不会生成新的补偿边。

从最远点仅传播一次：最远点的直接邻居可以成为上沿，但不会继续沿邻居递归传播。相机已标定时，沿边排序采用去畸变几何坐标，显示和角点键值仍使用原始图像坐标。

## 5. 画面和使用方式

原有中心点颜色保留：黄色为可见角点，品红色为补偿角点。外圈和标签说明如下：

| 外圈 / 标签 | 含义 |
| --- | --- |
| 橙色 `UP` | 最远点或与其直接相连的上沿假设 |
| 青色 `LOW*` | 最近下沿种子，替代本测试模式下原有的近处参考圈 |
| 绿色 `LOW` | 与种子距离满足底边长或宽的其他下沿点 |
| 无新增外圈 | 保留的未分类候选 |

点旁显示 `r` 为投影距离。超出定位量程但几何投影有效的点显示 `geom r=... | rank only`，仍可标为UP或LOW，但不用于地图匹配。参与长宽匹配的点还显示 `to LOW*`（距种子的距离）和 `e`（距长、宽两个标准值的最小误差）。侧栏显示候选数、上下沿数、容差及状态，`LOW` 数量包括种子。

按 `P` 打开参数窗口，调整 `bottom tol mm`。本分支通过原有 `run_app.py` 启动完整程序时，默认测距和平面Z=0满足启用条件。

仅运行相机识别的示例（项目目录内）：

```powershell
.\.venv\Scripts\python.exe .\purple_camera_segmentation.py --camera usb0bda3035_1080p --scene auto --ranging --target-z-mm 0 --range-max-mm 1000 --bottom-edge-tolerance-mm 30
```

向该相机脚本追加 `--no-bottom-edge-test` 可以关闭新增分类。该开关属于相机脚本，未新增到完整程序启动器的参数中。

## 6. 输出数据

启用测距并配置实时关联输出时，`latest.json` 新增 `bottom_edge_test`。按 `S` 保存的测距快照也包含相同字段。

- `schema`：`safety.bottom_edge_test.v1`。
- `candidate_count`：去重后的候选数。
- `ranking_count`：可用于全体排序的几何投影数量；侧栏 `N` 显示此数/全部候选数。
- `eligible_count`：符合当前定位测距条件的数量；1000毫米外的点可能参与排序，但不计入此数量。
- `corners[].localization_eligible`：该点能否作为定位测量，独立于上下沿分类。
- `upper_seed`、`lower_seed`：最远上沿种子、最近下沿种子的原图像素坐标。
- `corners`：保留全部候选及其类别、原因、测距和长宽误差。
- `connections`：实际支撑线连接，包含两端像素和线编号。
- `lower_seed_has_edge_length_match`：是否另有至少一个点通过与种子的长宽匹配。
- `layer_labels_are_hypotheses=true`、`map_identity_verified=false`：分类假设和地图身份确认分开表达。

主要状态：`classified`（≥3个时完成规则）、`nearest_fallback`（1或2个时取最近点）、`no_candidates`、`no_remaining_candidates`、`ranking_incomplete`、`unmeasurable_or_wrong_plane`、`ground_ranging_required`。`classified`本身不表示高度、地图身份或定位精度已被验证。

## 7. 验证记录

### 当前恢复1000毫米上限的原因

本次工作区142项、独立提交快照140项相关测试通过。1080p模拟流程中4个候选全部参与排序，3个超量程点仍保留；只有量程内下沿点参与惯导先验与地图匹配。最远补偿点仍是UP种子，最近剩余点仍是LOW*，地图匹配不改变上下沿类别。

2026-10-14：用户反馈画面明显卡顿。诊断确认，无上限路径每帧重复3次动态地面视野多边形裁剪，视野相关累计耗时达2795.7毫秒，因此恢复默认1000毫米定位上限，并复用启动时缓存的固定车体系视野。完整候选几何排序、最远补偿点参与排序及一次邻接传播继续保留。

恢复后使用真实标定参数做30次离线基准，视野预筛与地图关联阶段中位耗时5.414毫秒，范围5.336～5.757毫秒；启动时建立一次视野约742.98毫秒。基准和4组变化位姿检查均禁止每帧重建车体系多边形，仍通过，确认复用了缓存。此测量不包含图像识别、相机采集及窗口显示，不能换算为整体FPS。记录位于 `tmp/fps_restore_20261014/benchmark_restore.json`，不提交。以下测试数量和相机样本属于注明的历史版本。
