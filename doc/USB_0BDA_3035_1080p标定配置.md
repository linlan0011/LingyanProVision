# USB Camera（VID_0BDA / PID_3035）固定标定配置

当前设备 ID 为 `0BDA:3035`，与 SP3220L（`1871:0501`）不同。独立相机配置名称：`usb0bda3035_1080p`。采图、内参、安装点、外参及验证数据均使用这个名称，不使用 `lingyan` 或 `sp3220l_1080p` 的目录。

成像模式固定为 **1920×1080、30 FPS、不旋转**；在本机通过 **Media Foundation（MSMF）** 读取，配置后实际读取约 30.1 FPS。驱动列出的 1080p 30 FPS 压缩源模式为 MJPG，OpenCV MSMF 返回的是解码后的彩色图像，其 FOURCC 查询值不能用来判断原始压缩源格式，因此不对 MSMF 强行设置 DirectShow 的 FOURCC 属性。

参考 Windows 默认相机应用的实际预览设置。Windows 相机当前使用自动曝光和自动白平衡；曝光即时回读值为 -5，白平衡控制回读值为 6500，但这些读数不是固定输出。为了棋盘采图，曝光保持手动 -5；白平衡使用与 Windows 相机相同的自动模式。其他参数通过驱动接口回读并沿用：

| 项目 | 固定值 |
| --- | ---: |
| 曝光（驱动整数单位） | -5，手动 |
| 白平衡 | 自动（Flags=1）；驱动初始控制值 6500，不表示锁定色温 |
| 亮度 | 0 |
| 对比度 | 40 |
| 色调 | 0 |
| 饱和度 | 66 |
| 锐度 | 50 |
| 伽马（驱动单位） | 350 |
| 背光补偿 | 0 |
| 增益（驱动单位） | 64 |

各采图和识别入口会先核对 USB 标识，再应用手动参数和明确记录的自动控制模式，并回读验证；失败会停止。白平衡是有意保留的自动控制例外：实拍显示，直接把自动模式读数 6500 改为手动白平衡会明显偏绿，不能通过复制一个数值复现 Windows 相机的颜色。驱动未暴露额外的颜色增益控制，目前无法锁住完全相同的颜色输出。采集中保持照明稳定；以后颜色识别仍需在实际照明下验证阈值。

焦点／自动对焦／变焦没有可用的驱动控制接口，不能声明已经软件锁定：保持镜头机械位置不动，棋盘清晰后再拍摄。光照过暗时增加照明，避免采集中随意改曝光。如果确需改镜头焦点或成像条件，应单独保存新配置并重新拍摄。

因用户反馈画面较暗，实际对比后将曝光由 -6 改为 -5。随后按用户要求参考 Windows 相机应用，恢复自动白平衡以消除明显偏青／偏绿。调整时训练目录尚无棋盘照片，旧采集元数据、Windows 实际控制读数及对比图保留在 `exposure_checks/`。自动白平衡模式也写入采集和标定结果元数据，不能与旧手动白平衡数据混用。30 FPS 是请求值，实际读帧速度以运行时计时为准。

训练照片采集：

```powershell
Set-Location "C:\Users\24435\Desktop\LingyanProVision"
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera usb0bda3035_1080p
```

使用 9×6 内角点棋盘。完整检测到 `FOUND` 后，停稳按空格保存原始 1920×1080 图片；预览缩小只用于辅助采图。拍 24～30 张，覆盖不同距离、左右上下位置、四角及不同倾斜方向。Q／Esc 退出。训练目录：`calibration/data/usb0bda3035_1080p/train/`。

独立验证照片另拍 6～10 张：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera usb0bda3035_1080p --output calibration/data/usb0bda3035_1080p/validation
```

训练和验证拍好后，以当前实体棋盘的实测单格长度求内参；不要直接沿用旧棋盘记录值而不复核：

```powershell

& ".\.venv\Scripts\python.exe" -m calibration.validate_intrinsics --camera usb0bda3035_1080p
```

后续安装外参和独立测距验证仍需分别完成。使用相同相机 ID 和固定成像设置，所有点坐标相对于同一个车体原点。内参文件会记录 USB 标识、采集后端和固定参数；配置不匹配时不能套用。

## 相机控制接口报 E_ACCESSDENIED

本机实测：Microsoft Store 版 PowerShell 7.6.6 在 DirectShow `IMoniker.BindToObject` 阶段返回 `0x80070005`；Windows 自带 PowerShell 和非打包版 PowerShell 均能读取同一设备的 11 项控制参数。旧代码优先从 PATH 查找 `pwsh`，因此用户终端和 Codex 环境表现不同。

`camera_controls.py` 现优先使用 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`，不依赖用户终端的 PATH 顺序。无需更改系统权限或以管理员身份启动；相机身份核对和参数回读仍会执行。已有照片和相机配置不变。仍应避免同时打开多个取流程序。

## 首轮视觉 HSV 参数（2026-10-02 实拍）

为 `usb0bda3035_1080p` 单独设置了紫色分割阈值；原灵眼和逐飞相机的阈值及场景规则保持不变。当前画面中可见安全区紫色的代表性像素色相约为 H=126–141，旧的 H=115–175 范围偏宽，且紫色阴影亮度低于旧 V=40 门槛。因此该相机的三个识别场景统一采用：

| 参数 | 当前值 |
| --- | ---: |
| H 下限 | 120 |
| H 上限 | 150 |
| S 下限 | 55 |
| V 下限 | 25 |

白色场地的阈值与几何识别规则按对应场景原值继承。对 2026-10-02 19:14 左右抓取的单帧回放，紫色连通区域从 5 块降为 3 块，两个主要安全区片段仍保留（约 4,062 和 1,448 像素）。该画面中安全区较远且大部分被笔记本遮挡；此参数是现场首轮值，后续需在安全区近距离、远距离和不同照明下复核。
