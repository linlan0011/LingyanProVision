# 多相机标定与选择

一台相机的一个固定成像模式对应一个独立相机 ID。模式包含物理设备、采集分辨率、画面旋转、镜头/对焦位置和镜头模型。所有采图、点位、内外参和验证结果按该 ID 存在独立目录。原灵眼使用 `lingyan`，彩钻风配置使用 `seekfree`；后一项目前没有已求出的内外参。第三台新相机请另起 ID，例如 `hd_cam1`，不要把它登记为 `seekfree`。

2026-09-30 已把现有灵眼数据和结果另存于 `calibration/backups/lingyan_20260930_before_multicamera.zip`。旧 `intrinsics.json` 保留；旧 `mount_pose.json` 含不合理的光心坐标，不能用来测距。备份保存历史状态，不代表其中所有结果有效。

## 0. 确定新相机的实际模式

关闭其他占用摄像头的程序，在项目根目录 PowerShell 中运行：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.probe_camera --index 0
```

查看 `actual WxH` 且标为 `EXACT` 的高分辨率模式。若设备不在序号 0，改 `--index 1` 等。这个程序只读尺寸和驱动报告帧率，不能根据画面或 Windows 枚举名证明相机的真实型号。型号未知时给它起一个明确的项目 ID，并记录设备标识、镜头对焦及选定模式。一次只留待测试设备接入更易核对序号。

## 1. 登记相机

以下命令的 **1920、1080、0 只是填写位置的示例**，不要照抄；换成上一步实际接受的宽、高和序号。画面不旋转用 `none`。普通针孔镜头先用 `opencv_pinhole`；确认为鱼眼后选 `opencv_fisheye`，两种模型的畸变参数不通用。

```powershell
& ".\.venv\Scripts\python.exe" -m camera_profiles add hd_cam1 --name "我的高清摄像头" --width 1920 --height 1080 --rotation none --model opencv_pinhole --index 0 --notes "记录镜头、对焦及设备标识"
& ".\.venv\Scripts\python.exe" -m camera_profiles list
```

`camera_profiles.json` 记录新增的相机。已有 ID 不能重定义；如果换分辨率、镜头、焦点或画面方向，再注册另一个 ID。旧灵眼配置仍是 640×480、不旋转。采图脚本会核对设备实际帧尺寸；驱动回退到别的分辨率时会停止。

## 2. 用同一块棋盘采集内参照片

棋盘继续使用 9×6 内角点，实体单格长度以打印后实测值为准。原灵眼当时输入的 19.12 mm **不能替代这次对棋盘的实测**。新相机镜头可能有不同视场，要使棋盘在画面中心和四角都有充分覆盖，距离和倾角也应明显变化。求参照片建议 20～30 张，另留 6～10 张不参与求参的验证照片。

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera hd_cam1
& ".\.venv\Scripts\python.exe" -m calibration.capture_chessboard --camera hd_cam1 --output calibration/data/hd_cam1/validation
```

空格保存识别成功的棋盘，`q`/Esc 退出；求参集落在 `calibration/data/hd_cam1/train/`，验证集落在 `validation/`。数据应是匹配该 ID 的原始成像方向；显示窗口的缩放不修改图像尺寸。拍摄中不要改对焦、分辨率或方向。

## 3. 解内参并独立验证

把下面的 `实测单格毫米数` 换成数值。程序会求 `K`、普通镜头的 `k1,k2,p1,p2,k3`，或鱼眼模型的四个系数，写入该相机自己的结果目录。

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.calibrate_intrinsics --camera hd_cam1 --square-mm 实测单格毫米数
& ".\.venv\Scripts\python.exe" -m calibration.validate_intrinsics --camera hd_cam1
```

查看 `calibration/results/hd_cam1/intrinsics.json`、`validation.json` 和 `validation_previews/`。检查求参、验证重投影误差及画面边缘矫正。低重投影误差不足以证明纸张平整或真实距离准确。

## 4. 装车外参

用最终比赛安装姿态固定相机，定义统一车体系 X 向前、Y 向左、Z 向上。新相机的安装位置与旧灵眼通常不同，需重新量大致光心并采集实测点。使用冻结点选工具，导出至少 12 个遍及远近、左右的真实 `(X,Y,Z) ↔ (u,v)`；不要把灵眼点位复制过来。

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.collect_mount_points --camera hd_cam1
& ".\.venv\Scripts\python.exe" -m calibration.fit_mount_pose --camera hd_cam1
```

CSV 默认在 `calibration/data/hd_cam1/mount_points.csv`，拟合结果在 `calibration/results/hd_cam1/mount_pose.json`。核对求得的光心位置、内点数和误差是否符合实测。相机或车体原点移动后要重新采集。

## 5. 用独立点验证测距

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.collect_mount_points --camera hd_cam1 --purpose validation
& ".\.venv\Scripts\python.exe" -m calibration.validate_ranging --camera hd_cam1
```

验证点不能重复使用外参拟合点。结果位于 `calibration/results/hd_cam1/range_validation.json`，需要覆盖比赛实际测距范围。当前所有脚本按已知点高度做射线与平面求交，目标高度未知时不能仅凭单目像素得到米制距离。

## 6. 选择相机运行识别

```powershell
& ".\.venv\Scripts\python.exe" run_app.py --camera hd_cam1
```

或者只运行识别窗口：

```powershell
& ".\.venv\Scripts\python.exe" purple_camera_segmentation.py --camera hd_cam1 --scene auto
```

脚本按 ID 取采集模式、识别参数和匹配的内外参，并核对尺寸与模型。没有有效内外参的相机仍可作为普通识别预览，但不应发布米制测距结果。新相机暂用通用的紫色边框识别规则，仍需在新画面上实拍调颜色阈值、角点容差和身份编号效果。当前识别程序只显示角点和识别结果；米制测距需在新相机的独立点验证合格后再接入实时识别输出。

需要检查某个像素的已知高度平面投影时，可运行：

```powershell
& ".\.venv\Scripts\python.exe" -m calibration.ground_project 320 360 --camera hd_cam1 --target-z-mm 0
```

坐标 `320 360` 是示例，必须替换为该相机原图的真实像素。所有输出均相对你测量地面点时定义的同一个车体原点。
