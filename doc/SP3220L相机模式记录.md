# SP3220L 相机成像模式记录

记录日期：2026-09-30。Windows 当前把接入的 USB 相机枚举为 `SP3220L`，硬件标识 `VID_1871&PID_0501`，状态 `OK`。`SP3220L` 是系统报告的设备名称，不等于已确认的厂商或镜头型号。

用户通过 `calibration.probe_camera` 得到以下模式；我另外在当前工作环境复核了 1280×960 和 1920×1080 均可实际出帧：

| 请求宽×高 | 实际宽×高 | 结果 |
| --- | --- | --- |
| 640×480 | 640×480 | EXACT |
| 1280×720 | 1280×720 | EXACT |
| 1280×960 | 1280×960 | EXACT |
| 1280×1024 | 1280×960 | 回退 |
| 1600×1200 | 1920×1080 | 回退 |
| 1920×1080 | 1920×1080 | EXACT |
| 2048×1536 | 1920×1080 | 回退 |
| 2560×1440 | 1920×1080 | 回退 |

当前已登记独立配置 ID：`sp3220l_1080p`，**采集 1920×1080、不旋转、暂按 OpenCV 普通针孔模型**。这只是完成标定前的模型选择；若留出验证显示明显系统性边缘误差，应重新检查镜头模型。参数目录为 `calibration/data/sp3220l_1080p/` 和 `calibration/results/sp3220l_1080p/`，不会读写灵眼目录。1920×1080 的原始彩色帧已成功读取并保存在 `calibration/data/sp3220l_1080p/device_check_1920x1080.png`。

最初默认 YUY2 测到 **1280×960：7.0 帧/秒；1920×1080：4.8 帧/秒**。随后读取完整驱动能力表并纠正设置顺序，确认相机支持高分辨率 MJPG：所有 10 档分辨率的 MJPG 驱动上限均为 25 帧/秒，逐档连续约 150 帧实测均为 **24.93～25.00 帧/秒**。1920×1080 的 MJPG 实测约 **25.00 帧/秒**。

此前“请求 MJPG 会回退到 YUY2”只适用于错误的属性设置顺序。DirectShow 应先设置宽高及 FPS，**最后设置 FOURCC=MJPG**，并读取实际 FOURCC 核对；再次设置分辨率或 FPS 会把它切回 YUY2。用户已选择最高分辨率开始标定，正式 `sp3220l_1080p` 配置现已固定为 **1920×1080、MJPG、25 FPS、不旋转**；棋盘采集、安装点采集和实时识别均沿用这一设置并检查实际 FOURCC。完整实测见 `calibration/benchmarks/sp3220l_fps_20260930_205322_248455.md` 和同名 JSON。

驱动报告帧率有时是 `-1`，显式请求 30 FPS 后虽可能报告约 30 FPS，但不能突破驱动能力表的 25 FPS 上限。读帧速度还会受 USB、光照、曝光和本机处理影响；在完整识别程序中应另外实测运算后的帧率。YUY2 对照测试后半段出现了读帧失败，失败项不能解释为帧率为零。

DirectShow 属性读取到亮度 0、对比度 36、饱和度 72、自动白平衡 1、色温 4600、伽马 100、锐度 2。焦点、自动对焦、变焦、曝光、自动曝光和增益均返回 `-1`，表示这条 OpenCV 读取路径没有提供可用值，不能据此断言这些功能不存在或已经锁定。

最初检查原图几乎全黑；本次 MJPG 测速期间已读取到更明亮画面，但尚未验证棋盘角点或镜头畸变。在明亮场地使棋盘清晰可见后，再拍训练和独立验证照片。使用 [多相机标定说明](多相机独立标定与切换.md) 中的流程，并将示例 ID 换为 `sp3220l_1080p`。实际拍摄前复核实体棋盘单格边长和最终镜头焦点。内参、安装外参、独立测距验证目前都还未生成。
